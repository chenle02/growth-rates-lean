# GrowthRates agent guidance

Read README.md (What is proved, Not proved here, Trust and axioms) before you edit. Check `git status` first and keep
other contributors' uncommitted work.

## Authority

1. The Lean declaration decides every hypothesis and quantifier.
2. `claims.yaml` lists every public theorem and lemma; `status: reusable` marks the ones stated in the
   comparator Challenge. `comparator.json` lists the statements that are compared, and
   `GrowthRates/Challenge.lean` holds their trusted Mathlib-only text.
3. The generated verification block in README.md, `docs/verification.md`, `docs/coverage.md` and the receipts
   under `.lean-receipts/` record what was checked and at which commit. A receipt covers only the content it
   names.
4. Prose in README.md, `llms.txt` and `docs/` describes the results. Lean does not check it.

## Scope

The library proves Fekete-type limit theorems for real functions of a real time variable, uniform envelopes
over an order parameter, and finite-time errors, all from explicit hypotheses. Local boundedness and
nonnegativity are hypotheses of the continuous-time Fekete lemma (there is no measurability-only version).
There is no general de Bruijn–Erdős theorem and no convergence rate in the Fekete lemmas. Every comparison,
cut, confinement and composition inequality, and every fixed-order limit and lower error of the envelope
results, is a hypothesis and is not derived for any concrete model. There is no probability and no PDE
content. Do not describe any of these as proved.

## Working rules

- Use the pinned `lean-toolchain` and `lake-manifest.json` together. Never run `lake update` in this
  repository during a verification run.
- Compile changed modules locally before starting a long verification run.
- Keep the Lean source, `claims.yaml`, `comparator.json`, `GrowthRates/Challenge.lean`,
  `GrowthRates/Solution.lean`, `GrowthRates/Axioms.lean`, `coverage.yaml`, the README result list,
  `docs/what-is-proved.md` and `docs/modules.md` in step. A renamed, added or weakened theorem must change all
  of them.
- Do not strengthen a theorem in prose. Keep visible wherever a result is described: the `RealTimeBounds`
  fields (nonnegativity, subadditivity, the local upper bound), `M, B ≥ 0` and `h ≥ 1` with monotonicity and
  the linear upper bound for the logarithmic defect, the antitone-in-order hypothesis of the joint limit, and
  the assumed rate `lam` with the cut, confinement and composition inequalities of the finite-time error.
- The only permitted axioms are `propext`, `Quot.sound` and `Classical.choice`. No `sorry`, `axiom`,
  `opaque` or `native_decide` in the library modules. `GrowthRates/Challenge.lean` (by design) and the
  disabled negative controls in `GrowthRatesTest/` are the only exceptions.
- A negative control (`GrowthRatesTest/Neg*.lean.disabled`) must keep failing for a mathematical reason;
  run `bash scripts/check-negative-controls.sh` after `lake build GrowthRates`.
- Never fabricate a receipt, and never let a receipt for one commit stand for changed source.
- Keep private paths, unpublished drafts and internal process names out of the repository and its history.
- No GitHub Actions workflows. `docs/verification.md` and `docs/coverage.md` are generated by
  `lean-pkg page --site docs`; never edit them by hand, and never hand-write the README block between the
  `lean-pkg:page` markers or a computing acknowledgment (`lean-pkg page` generates it from the recorded receipts).
